## 2026-08-20：阶段 1 补充，多 Agent 配置和隔离基础

### 做了什么

- 支持扫描 `configs/agents/*.json`，按 `agent_id` 加载多个 Agent。
- 重复的 `agent_id` 会直接报错，避免两个 Agent 配置互相覆盖。
- SQLite 的 `sessions` 表增加 `agent_id`，旧数据库会自动补默认值 `ecom-default`。
- 新增登录后的 `GET /agents`，可以查看当前可用 Agent 的基本信息。
- `/sessions` 和 `/chat` 支持传入 `agent_id`。
- 同一用户在不同 Agent 下使用不同会话，不能把一个 Agent 的会话拿给另一个 Agent 继续使用。
- RAG 工具支持按配置使用不同目录下的 `index.json`；默认 Agent 仍使用原来的 `data/index.json`。

### 为什么这样做

只把名字和 Prompt 配置化还不够。如果会话和知识库仍然全局共用，用户切换 Agent 后会串上下文或查到别人的知识。现在先把隔离边界建立起来，后面再做上传和管理页面。

### 遇到的问题和解决方法

- RAG 自定义工具第一次测试时仍然调用了全局 Retriever，导致自定义 Agent 查到了默认知识库。
- 已把检索逻辑改为使用传入的 Retriever，并让自定义索引延迟加载，避免 Agent 启动时就因为索引不存在而失败。

### 验证结果

- 配置目录、重复 ID、Agent 列表 API、会话隔离和 RAG 隔离测试均通过。
- 全部测试共 54 个，通过。
- `compileall` 通过。

### 当前状态

基础多 Agent 隔离完成。现在可以通过新增 JSON 配置创建不同 Agent，但还不能通过页面上传配置和知识库。

### 下一步

做知识库管理：先支持 Markdown 文件的安全校验、切片和索引输出，再接上传 API。

## 2026-08-20：阶段 5 前置，知识库处理模块

- 只接受 `.md` 文件，限制默认大小为 2 MB。

- 知识库路径不能只影响 Prompt，还必须影响真正的 Retriever 和索引文件。
- 已让检索工具按 Agent 配置延迟加载对应索引，避免不同 Agent 共用默认索引。

## 2026-08-20：阶段 5，管理员知识库上传

### 做了什么

- 增加 `GET /admin/agents/{agent_id}/knowledge`，查看文件列表和索引是否就绪。
- 增加 `POST /admin/agents/{agent_id}/knowledge`，管理员可以上传 Markdown 文件。
- 上传接口限制 UTF-8、`.md` 后缀和 2 MB 大小。
- 拒绝路径穿越、同名覆盖和普通用户上传。
- 上传后自动执行切片和索引构建。
- 索引构建失败时删除本次新文件，避免留下未进入索引的文件。
- 使用 `python-multipart` 支持 FastAPI 文件上传。

### 为什么这样做

知识库上传必须是完整流程：文件进入系统后要能校验、保存、切片和向量化。权限和失败回滚也要在第一版就有，不能让任何用户直接修改共享知识库。

### 遇到的问题和解决方法

- 文件上传依赖 multipart 解析，项目原来没有对应依赖。
- 已通过 `uv add python-multipart` 加入项目依赖，并更新锁文件。

### 验证结果

- 新增知识库 API 测试 3 个，通过。
- 全部测试共 60 个，通过。
- `compileall` 通过。

### 当前状态

## 2026-08-21：阶段 8 第三部分，登录失败限流

### 做了什么

- 增加单进程登录失败计数器。
- 同一客户端和账号 60 秒内连续失败 5 次后，暂时返回 429。
- 429 响应带 `Retry-After`，前端可以知道大概多久后重试。
- 成功登录后清除该账号的失败计数。
- 增加限流测试，并给 429 增加 `TOO_MANY_REQUESTS` 错误码。

### 为什么这样做

登录接口容易被反复尝试。当前项目还是 SQLite 单实例学习版，用内存限流就能先提供基本保护，不额外引入 Redis。

### 边界

这个限流器只对当前 Python 进程生效。以后用多个后端进程或多台服务器时，要把计数放到 Redis，才能让所有实例共享限制。
