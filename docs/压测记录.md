# 压测记录

执行时间：2026-08-22

工具：Locust + 独立 Docker Compose

环境：i7-13650HX、15.7 GB 内存、1 个 Uvicorn worker、隔离 PostgreSQL 和 Redis。

## 第一轮：发现问题

第一轮让每个 Locust 用户现场注册、登录，再进入业务接口。结果：

| 场景 | 请求 | 错误率 | 平均 | P95 |
| --- | ---: | ---: | ---: | ---: |
| 300 用户读取 | 4456 | 0% | 3447ms | 9800ms |
| 150 用户写入 | 3271 | 56.71% | 3129ms | 7400ms |
| 500 用户混合 | 5219 | 23.36% | 8366ms | 18000ms |
| 2000 用户峰值 | 2562 | 0% | 44857ms | 77000ms |

2000 用户阶段实际只有部分用户完成登录，不是真正的 2000 个活跃业务用户。

后端日志出现：

```text
psycopg.errors.DeadlockDetected: deadlock detected
```

原因：注册、鉴权、订单、商品、退款和 Agent 创建等请求路径会反复调用 `init_db()`，并发执行建表、建索引和种子数据 DDL。数据库异常还被鉴权代码错误包装成 `401 Token 无效`。

## 修改

- `init_db()` 只在 FastAPI、CLI 和 MCP 服务启动时执行。
- 普通业务请求只执行查询或写入 SQL。
- JWT 无效返回 401；数据库查询异常返回 503。
- 增加 4 条回归测试，修改前全失败，修改后全部通过。
- 预置压测账号、JWT 和会话，让峰值用户直接进入业务接口。
- 认证突发单独测试，阶段间增加冷却时间。
- 每 5 秒记录 backend、PostgreSQL 和 Redis 的 CPU/内存。
- 汇总器支持 UTF-8/GB18030，并在报告失败时返回错误。

## 第二轮：正式结果

命令：

```powershell
.\load_tests\run.ps1 -Profile full
```

| 场景 | 请求 | 失败 | RPS | 平均 | P95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 500 用户读取 | 11226 | 0 | 148.73 | 2719ms | 3200ms |
| 200 用户认证突发 | 2294 | 0 | 34.01 | 5309ms | 6000ms |
| 300 用户业务写入 | 8610 | 0 | 92.85 | 2795ms | 4000ms |
| 1000 用户复杂读写 | 15916 | 0 | 126.46 | 7270ms | 8800ms |
| 3000 用户突发峰值 | 13724 | 0 | 137.03 | 19302ms | 23000ms |
| 5 用户真实聊天 | 24 | 0 | 0.39 | 6881ms | 11000ms |

日志复查：死锁、Traceback、401、500、503 均为 0。WeKnora 日志确认聊天阶段实际执行了知识库检索 SQL，不是只调用聊天模型。

资源峰值中最明显的是认证阶段：backend CPU 约 1506%，内存约 2.28 GiB，主要来自 200 个并发 Argon2 密码哈希。3000 用户阶段 backend CPU 约 258%，PostgreSQL 约 202%。

## 结论

- 重复 DDL 死锁已经解决，写入错误率从 56.71% 降为 0%。
- 1000 用户复杂读写没有报错，但 P95 8.8 秒，已经明显排队。
- 3000 用户阶段 P95 23 秒，停止时仍有任务未完成，不能称为支持 3000 并发。
- 当前限制主要是单 worker 的请求处理能力和认证哈希资源消耗，不是 Redis。
- 这是单机学习环境结果，不代表生产容量；本项目不继续做生产级扩容。
