# 2.0 开发计划

## 目标

把 1.0 的电商客服 Agent 改造成可配置的通用 Agent：用户可以更换角色、提示词、知识库和工具，不需要修改核心代码。

## 开发阶段

### 阶段 0：冻结 1.0

- 保留 `v1.0.0` Release 作为稳定版本。
- 2.0 使用独立分支开发。
- 确认 API Key、数据库和临时文件不会进入仓库。

### 阶段 1：Agent 配置化

- 定义 Agent 配置模型。
- 配置名称、角色、欢迎语、语气、模型和温度。
- 配置知识库目录和启用的工具。
- 保留电商配置作为默认示例。

### 阶段 2：Prompt 模板化

- 固定安全规则和输出规则。
- 从配置加载 Agent 名称、角色和服务范围。
- 动态加入工具说明和 RAG 内容。
- 不再把“小极”和“极客商城”写死在核心代码里。

### 阶段 3：工具可插拔

- 统一工具注册格式。
- 按 Agent 配置启用或关闭工具。
- 给工具增加权限和确认规则。
- 保留人工转接能力。

### 阶段 4：数据层升级

- 抽象数据库访问接口。
- SQLite 继续作为本地学习模式。
- PostgreSQL 作为多用户部署模式。
- 使用 pgvector 保存知识库向量。
- Redis 后续用于缓存、队列和限流。

### 阶段 5：知识库上传

- 第一版支持 Markdown。
- 后续支持 TXT、PDF 和 Word。
- 上传、解析、切片、向量化和索引建立自动完成。
- 支持查看状态、删除、重新索引和失败重试。

### 阶段 6：多用户和多 Agent

- 用户只能访问自己拥有的 Agent。
- 每个 Agent 使用自己的提示词、工具和知识库。
- 会话、消息和检索结果按 `user_id`、`agent_id` 隔离。

### 阶段 7：API 和管理员页面

- 创建、修改、删除 Agent。
- 上传和管理知识库文件。
- 配置工具开关和 Prompt。
- 查看处理任务、会话和错误记录。

### 阶段 8：可靠性和安全

- 文件类型、大小和内容校验。
- API Key 只保存在服务端。
- Prompt 和配置支持版本与回滚。
- 增加日志、限流、备份和数据清理策略。

### 阶段 9：测试和开源发布

- 通用 Agent 单元测试和接口测试。
- 知识库上传和检索测试。
- 多用户隔离测试。
- Docker Compose 一键启动。
- 更新 README、配置示例和 2.0 Release。

## MVP 范围

第一版 2.0 只完成：

```text
Agent 配置
+ Prompt 模板
+ Markdown 知识库
+ 工具开关
+ SQLite 本地模式
+ 基础多 Agent 隔离
```

PostgreSQL、Redis、PDF、管理员上传页面和异步任务放在 MVP 之后，避免一次做得太大。

## 当前进度

- 阶段 0 已完成：1.0 已冻结，2.0 使用 `v2.0` 分支开发。
- 阶段 1 已完成：配置模型、默认配置和运行时模型/工具开关已接入。
- 阶段 2 基础已完成：Prompt 已改为根据 Agent 配置生成；完整自定义 Prompt 放在阶段 9。
- 阶段 3 已完成：本地工具已整理为可注入的注册表。
- 阶段 1 补充已完成：多 Agent 配置、会话和 RAG 的隔离基础已建立。
- 阶段 4 尚未开始：暂时继续使用 SQLite，本地模式优先。
- 阶段 7 前置已完成：前端支持 Agent 切换和管理员知识库管理。
- 阶段 6 补充已完成：Agent 支持公开/私有状态和归属用户，用户只能看到和使用自己有权限的 Agent。
- 阶段 6 自助功能已完成：用户可以创建和修改自己的私有 Agent，并管理自己的 Markdown 知识库。
- 阶段 7 自助页面已完成：用户可以在 Vue 页面创建、编辑 Agent，并维护个人知识库。
- 阶段 7 生命周期补充已完成：用户可以删除自己创建的私有 Agent，并清理对应知识库目录。
- 阶段 7 真实验收已完成：登录、创建 Agent、上传 Markdown、索引和个人 Agent 聊天检索流程通过。
- 阶段 8 第一部分已完成：Agent 配置、Agent 初始化和知识库索引失败时，会返回明确的错误提示并记录服务端日志。
- 阶段 8 第二部分已完成：注册和登录输入有长度限制，JWT 配置缺失时返回 503，服务不可用错误码已统一。
- 阶段 8 第三部分已完成：登录失败次数受到单进程限流保护，过多失败会返回 429。
- 阶段 9 第一部分已完成：Agent 支持自定义 Prompt、行为规则和禁止主题，用户页面和管理员页面均可编辑。
- 阶段 9 第二部分已完成：增加 Prompt 预览接口，清理通用工作台中的商城硬编码；内部结构化输出格式继续由系统固定。
- 阶段 10 第一部分已完成：增加 WeKnora 搜索客户端和知识库提供方切换，默认 Agent 仍使用本地 RAG。
- 阶段 10 已完成：WeKnora 已真实启动并接通搜索、创建知识库、上传、解析状态、重新解析和删除；默认 Agent 已切换到 WeKnora，本地 RAG 保留为离线备用。
- 阶段 10 端到端验收已完成：上传 FAQ、异步解析、WeKnora 检索和客服纯文本回答均已跑通。
- 阶段 11 第一部分已完成：Redis 可选接入登录失败共享限流，未配置时继续使用本地内存限流。
- 阶段 11 第二部分已完成：当前项目业务数据库支持 SQLite 默认模式和 PostgreSQL 可选模式。
- 阶段 11 第三部分已完成：启动和 `/health` 会检查数据库状态并返回清晰错误。
- 阶段 8 第四部分已完成：Agent 配置支持版本快照、查看和回滚；删除私有 Agent 会清理关联数据。

阶段 8 尚未全部完成，备份策略仍待实现。

## 当前下一步

WeKnora 聊天链路和 Agent 配置回滚已经完成。下一步处理真实业务工具的适配边界；正式数据库迁移、异步任务和生产部署暂不展开。

## 2.0 后续路线

### 阶段 9：通用 Agent 和 Prompt 自定义

- 增加用户可填写的自定义 Prompt。
- 增加行为规则、回答风格、禁止事项和回答格式配置。
- 固定安全规则和用户 Prompt 分开，避免用户 Prompt 覆盖安全边界。
- 移除核心 Prompt 中的电商专用内容，电商规则只放在默认配置中。
- 移除前端中的商城硬编码，让不同 Agent 使用自己的名称和服务范围。
- 增加 Prompt 预览、测试和长度校验。
- 普通用户继续只能使用允许的工具，不能通过 Prompt 绕过权限。

### 阶段 10：接入 WeKnora

- 使用 WeKnora 作为独立知识库服务，不复制或修改其核心代码。
- 使用 WeKnora 的 PostgreSQL、Redis、文件存储和向量检索能力。
- 在当前项目增加知识库提供方接口和 WeKnora 客户端。
- Agent 配置保存 `knowledge_base_id`，不再依赖本地知识库路径。
- 上传、删除、重建和搜索知识库都通过 WeKnora 完成。
- 保留本地 RAG 作为过渡和离线 fallback。
- 用同一批问题对比本地 RAG 和 WeKnora 的准确率、延迟和成本。
- 确认效果后再移除本地切片、Embedding 和索引逻辑。

### 阶段 11：数据库和缓存升级

- 使用 PostgreSQL 保存当前项目自己的用户、Agent、订单、退款、会话和消息。
- WeKnora 使用自己的表或独立数据库，不能直接修改 WeKnora 的内部表。
- 用 Alembic 管理数据库迁移。
- SQLite 保留为本地学习模式。
- Redis 替换当前单进程限流，支持多进程共享限流计数。
- Redis 后续用于缓存和异步任务状态。

### 阶段 12：真实业务数据和工具接口

- 将订单、商品、物流和退款工具整理为服务层和数据访问层。（已完成第一步：接口和默认适配器）
- mock 数据只保留为演示模式。
- 预留真实电商 API、数据库或第三方系统的适配器。（已完成接口注入边界）
- 保持 Agent 只通过工具访问业务数据，不直接读取数据库。
- 增加工具权限、确认和审计记录。

### 阶段 13：正式运行能力

- 知识库索引改为异步任务。
- 增加文件对象存储和大文件限制。
- 增加配置版本、变更记录和回滚。
- 增加 PostgreSQL 备份、会话清理和知识库清理策略。
- 增加统一日志、健康检查、指标和错误追踪。
- 完善安全测试、权限测试和多用户隔离测试。
- 进行并发压测，重点测试聊天、检索和上传索引。

### 阶段 14：开源发布

- 提供本地学习模式和 Docker Compose 部署模式。
- Compose 模式包含当前 Agent、WeKnora、PostgreSQL、Redis 和前端。
- 完善 `.env.example`、README、API 文档和故障排查文档。
- 写清楚数据目录、密钥、许可证和第三方依赖声明。
- 创建 2.0 Release，保留 1.0 Release 不变。
- 用全新目录和知识库完成一次从安装到聊天的验收。

## 新路线的边界

- 不直接复制 WeKnora 的源代码到当前项目。
- 不让 WeKnora 管理订单、退款和电商业务数据。
- 不一次性删除当前 RAG、SQLite 和 mock 数据。
- 每完成一个阶段都要有测试、记录和独立提交。
