# 2.0 开发计划

## 目标

把本项目做成一个简单的 Agent 应用层，优先使用成熟开源项目：

    我们的项目：登录、权限、Agent、聊天、业务工具、前端
    WeKnora：知识库、解析、切片、Embedding、混合检索
    PostgreSQL：我们的用户、会话、消息和业务数据
    Redis：我们的共享限流和缓存状态

不再把主要精力放在自己实现一套简化版 RAG 或单文件数据库上。

## 阶段 1：核心边界

- 管理员配置 Agent、Prompt、模型、工具和知识库。
- 普通用户只选择公开 Agent、创建会话和提问。
- Agent 通过工具访问订单、商品、物流和退款。
- 用户不能通过 Prompt 绕过权限。

状态：已完成。

## 阶段 2：WeKnora 主路径

- 使用 Tencent/WeKnora 官方项目，不复制其源码。
- 使用官方 Docker Compose 单独启动 WeKnora。
- 本项目通过 REST API 调用 WeKnora。
- 上传、查询、重新解析和删除知识库文件都走 WeKnora。
- 检索使用官方推荐的 hybrid-search。
- WeKnora 知识库 ID 保存到 Agent 配置。
- 本地 RAG 只作为明确的离线备用模式。

状态：代码适配器已存在，本次任务正在把默认配置、前端和文档统一到这条路径。

## 阶段 3：应用数据库和缓存

- PostgreSQL 作为本项目默认数据库。
- Redis 作为本项目默认共享限流和临时状态服务。
- SQLite 仅保留为测试和离线学习模式。
- WeKnora 的 PostgreSQL 和 Redis 由 WeKnora 自己管理，本项目不直接访问其内部表。

状态：代码已经支持 PostgreSQL 和 Redis，本次任务正在把默认配置和 Compose 改为主路径。

## 阶段 4：Docker 和配置

- 本项目 Compose 启动 PostgreSQL、Redis、backend 和 frontend。
- WeKnora 使用官方 Compose，不复制到本项目 Compose。
- 本项目 frontend 使用 8088，避开 WeKnora 的 80 和 8080。
- .env.example 写清楚模型、WeKnora、PostgreSQL 和 Redis 配置。
- 启动失败时返回清晰的数据库、Redis 和 WeKnora 配置提示。

状态：本次任务进行中。

## 阶段 5：文档

- README 只说明项目定位、边界、启动和配置。
- 单独增加 WeKnora 接入说明。
- 更新 Compose 启动说明。
- 更新 API 接口清单。
- 更新 2.0 开发记录。
- 本地 RAG、SQLite 和旧学习过程保留为历史或备用说明，不伪装成当前默认架构。

状态：本次任务进行中。

## 阶段 6：验证

    Python 编译
    后端单元测试和接口测试
    WeKnora API 适配器测试
    前端构建
    Docker Compose 配置检查
    PostgreSQL 和 Redis Compose 启动检查

状态：代码和文档修改完成后执行。

## 边界

- 不复制 WeKnora 源码。
- 不修改 WeKnora 内部数据库。
- 不让模型直接拼 SQL 或 HTTP 请求。
- 不连接真实电商支付、订单或物流系统。
- 不把开源学习版包装成生产级系统。

## 完成标准

满足以下条件后，本次架构调整完成：

1. 新安装者能按 README 启动 WeKnora 和本项目。
2. 默认配置不再指向本地 RAG 和 SQLite。
3. 管理员上传文件后，文件进入 WeKnora。
4. Agent 检索调用 WeKnora hybrid-search。
5. 本项目应用数据进入 PostgreSQL。
6. 登录限流可以使用 Redis。
7. 所有当前文档对默认架构的描述一致。
