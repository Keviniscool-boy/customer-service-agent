# 业务连接器说明

当前项目默认是学习版，订单、商品、退款来自本项目 PostgreSQL，物流使用演示适配器。SQLite 只用于测试和离线学习。

以后接真实电商系统时，只替换业务连接器，不改 `agent/chat.py`、MCP 和前端。

## 订单和商品

实现 `BusinessRepository` 需要提供这些能力：

- 根据订单号和用户 ID 查订单
- 按关键词搜索商品
- 查询订单是否已有退款申请
- 创建退款申请
- 修改订单状态

连接器可以调用商家的 HTTP API、ERP 服务或自己的业务数据库。返回结果要转换成当前工具使用的字典格式，Agent 不需要知道外部系统的字段名。

## 物流

实现 `LogisticsProvider.query(tracking_number)`，返回：

- 物流单号
- 当前状态
- 当前地点
- 预计送达时间

当前 `DemoLogisticsProvider` 只是演示。真实版本可以换成快递公司的 API 适配器。

## 退款边界

退款会修改数据，聊天中必须先得到用户明确确认。没有确认时只返回待确认结果，不创建退款记录。

用户通过明确的退款接口提交时，仍然会按订单状态执行：未发货可以自动处理，已发货进入人工审核。

## 不要这样改

- 不要让 Agent 直接读取外部数据库。
- 不要把商家 API Key 放进 Prompt 或前端。
- 不要让模型自己拼接 SQL 或 HTTP 请求。
- 不要把外部平台的原始字段直接暴露给用户。

## 验证方式

先用 `Mock` 连接器测试工具行为，再接真实平台的沙盒环境。至少验证订单归属、查不到订单、物流无单号、重复退款和退款确认这几种情况。
