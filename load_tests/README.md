# 自动化全面压测

这里的压测使用独立 PostgreSQL、Redis 和 backend，不会把压测账号、订单和会话写入正常运行的数据库。结束后会自动删除隔离容器和 volume，不会停止正常项目与 WeKnora。

业务场景会先批量预置账号、JWT 和会话。这样高并发用户会直接进入业务接口，不会全部卡在注册和登录准备阶段。认证性能由单独场景测试。

## 自动测试内容

| 场景 | 目的 |
| --- | --- |
| 基础读接口 | 检查健康、商品、用户、Agent、会话、订单和退款查询 |
| 认证突发 | 检查注册、密码哈希、登录和 JWT |
| 业务写入 | 检查会话、订单、取消订单和退款完整写入链路 |
| 复杂读写混合 | 同时查询商品、订单、会话并创建/删除会话 |
| 突发峰值 | 缩短等待时间，观察过载时的错误率、排队和 P95/P99 |
| 真实聊天 | 低并发调用模型 API、WeKnora 和消息存储完整链路 |

`full` 配置会预置 3200 个隔离身份，依次运行：

- 500 用户基础读取，75 秒
- 200 用户认证突发，60 秒
- 300 用户业务写入，90 秒
- 1000 用户复杂读写，120 秒
- 3000 用户突发峰值，90 秒
- 5 用户真实聊天，60 秒

各阶段之间冷却 15 秒。真实聊天会消耗模型额度，并要求独立 WeKnora 已启动；其他场景不会调用模型。

## 一键执行

在项目根目录运行：

```powershell
.\load_tests\run.ps1
```

快速检查：

```powershell
.\load_tests\run.ps1 -Profile quick
```

跳过真实聊天：

```powershell
.\load_tests\run.ps1 -SkipChat
```

## 输出

- 汇总报告：`load_tests/压测报告.md`
- 修复前基线：`load_tests/压测报告-修复前.md`
- 原始 CSV、HTML 和日志：`load_tests/results/时间戳/`

原始结果默认不提交 Git，只保留在本机。中文汇总报告会保留在仓库中。

## 本次实测结论

2026-08-22 的完整测试所有已完成请求均为 0 失败，数据库日志没有再次出现死锁。3000 用户阶段 P95 为 23 秒，且停止时仍有任务未完成，因此不能解释成“支持 3000 并发”；它说明单 worker 已经严重过载。
